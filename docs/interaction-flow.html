OUTBOUND CALL — step by step

  1. Agent calls call.acquire{intent:"dial_out", enqueue?}.
  2. Line free → {granted:true, line_id, lease_id, expires_at}. All busy → {granted:false, free_lines[]} (retry later), or with enqueue:true → {granted:false, queued:true, ticket_id, position} plus event.queue_updated events as it advances; on grant — event.line_acquired{session_id, ticket_id, line_id, lease_id, intent, expires_at} (grant TTL to react, else next ticket; tickets are socket-bound).
  3. Agent calls call.dial("+373…", country:"MD") — strict E.164 + alpha-2 phonenumbers-region cross-check (uppercase alpha-2 incl. telephony extensions like XK/AC/TA, not strict ISO 3166-1 only; DIAL_REJECTED on failure, never reaches the line) → gateway → line.dial to the owning provider → oFono → phone dials (validated E.164 passed through unchanged). The lease arms pending_command:"dial" + a bounded ack deadline (provider_command_ack_sec, default ~2 s): the reply waits ONLY for the provider's {accepted, provider_call_id?} handshake distilled into ProviderCommandAck (round 33 — never for cellular alerting); refusal/timeout/unreachable → PROVIDER_UNREACHABLE, accepted → the reply carries provider_call_id?.
  4. Call reaches alerting → media attaches; event.audio_ready = local SCO path up (from provider.audio_ready); remote answer = event.call_state_changed{state:"active"} — greeting starts only on both.
  5. Duplex: agent sends audio frames (its voice) over the media channel → callee hears; callee's voice arrives as frames → agent listens/transcribes. call.send_dtmf("1") — IVR navigation.
  6. call.hangup queues line.hangup and returns immediately; the in-flight lease parks in terminating until the provider's disconnected or the hangup_hold_sec lapse ends it kernel-side (auto-release, rounds 22/32) → queue advances to the next agent.

INBOUND CALL — wake-and-grant

  1. Phone rings → provider reports ringing → gateway marks the line RINGING_LOCKED (outbound acquire on it fails LINE_BUSY_INCOMING).
  2. Gateway consults LineAssignment: owner exists → wake owner via hooks (webhook/exec/file-drop); no owner → event.incoming_call{line_id, call_token, caller_id?, expires_at} to live subscribers — one fanout envelope; ZERO live subscribers → one wake-audience envelope carrying the tokenless IncomingCallWakeEvent{line_id, caller_id?, expires_at} projection (no call_token — the live ring token reaches the woken agent only through its own authenticated event.incoming_call re-delivery after it registers) when hooks are configured, no envelope at all otherwise (round 33, PR #82 review — the ring still waits out the accept window).
  3. First call.accept(call_token) is atomic: lease + answer + media attach — the burned token parks the ring in answer_pending while the bounded line.answer handshake resolves (round 33 — reply waits for the ack only; refusal/timeout → PROVIDER_UNREACHABLE and the token never re-enters the fallback decision). Non-owner accept on an owned line → OWNER_MISMATCH; a second accept → STALE_TOKEN.
  4. event.audio_ready (from provider.audio_ready) + state == "active" → agent says "hello" (waiting for both avoids truncating the first word on Bluetooth lag).
  5. Nobody accepted within the window (default 30 s, all timeouts admin-configurable) → per-line fallback policy: no_pickup (carrier voicemail / keep ringing — the service does NOT drop or hijack the call) · forward_via_line · record_and_telegram · reject · answer_and_announce.

Deployment (target = prod)

Prototype (now)systemd user-service on the host — capability validation ONLY
ProdOne OCI container, --network=host + /dev/vhci on a dedicated host (round 25 — AF_BLUETOOTH is init_net-only; isolated netns is impossible; optional micro-VM profile for shared workstations deferred past MVP): BlueZ + PipeWire + dbus-daemon inside, all adapters are kernel vhci devices fed by hci-agents — no USB passthrough at all. Host bluetoothd is masked; listeners bind 127.0.0.1/wg0 + host firewall. Agents reach the container's socket (UDS 0660 / WSS / MCP); per-line worker bundles live inside it.
Remote site / any dongle hostOnly the hci-agent: dumb USB↔HCI relay (libusb, btusb detached), control-TCP + media-UDP over a transport_profile tunnel (wireguard default), heartbeat + remote USB reset; in-flight call on tunnel drop = hangup. A dongle on the gateway's own host uses the identical agent.

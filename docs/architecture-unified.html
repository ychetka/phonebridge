phonebridge — unified architecture

Principle: everything is registration. A line provider registers a "communication channel" with the gateway by address (127.0.0.1 or WAN) — one codebase. An agent registers an intent — one model. There is no difference between "phone nearby" and "phone far away" in the code.

Agents — any kind (Devin sessions, daemons, external systems)
Secretary agentintents: [receive_inbound, dial_out], exclusive on the "personal number" line
Outbound-campaign agentintents: [dial_out], takes lines from the pool
Other systemsn8n / scripts — via webhook events
▼ registration + RPC: agent.register_intent([...]) → JSON-RPC ns agent.*, call.* (Unix socket on host / WSS remotely, own token scope)
DOCKER container "phonebridge-gateway" — the single deployment artifact
Manager + APICallServicetwo surfaces of one daemon: Manager accepts provider.register/line.* from lines; APICallService accepts agent.*/call.* from agents; shared LineManager kernel; separate token scopes

▼ internal call to address 127.0.0.1 — the same protocol a remote provider uses

Unified model: three kinds of registration

WhoWhat is registeredLives while
Line providerprovider.register{line_id, caps, token} — a "communication channel"transport session + ping; lost → DEGRADED→DOWN
Agentagent.register_intent{dial_out|receive_inbound|exclusive_line} — an "intention"declarative; LineManager resolves intents → LineAssignment
Line ownershipLineAssignment (durable, survives sleep) — derived from intent OR admin_pinuntil release / revoke / idle alert

Inbound call under any topology

  1. Phone rings → provider (local or Pi — no difference) reports it to the gateway → line goes RINGING_LOCKED.
  2. Gateway consults LineAssignment: owner exists → wakes it via webhook/event; no owner → notifies live subscribers per the line's inbound policy.
  3. Woken agent: call.accept(call_token) → atomically lease+answer+media. Non-owner → OWNER_MISMATCH. Timeout → per-line fallback policy (default: phone rings on to carrier voicemail as usual).

Deliberate asymmetries (per consultation)

One transportJSON-RPC 2.0 + packetized media — one format everywhere
Different namespacesprovider.* vs agent.*/call.* — separate token scopes; an agent cannot call provider methods
Intent ≠ Assignmentintent is a declarative wish; LineAssignment is durable truth; conflicts = explicit error; admin-override remains
Media not symmetricWAN leg only: jitter buffer + audio watchdog; Opus/WebRTC = upgrade path
Deployment1 container, several processes (supervisord); local provider = separate process for code symmetry, NOT a separate container
